¿Qué es Arduino y qué placa elegir?

Arduino es una plataforma de electrónica y programación de código abierto: una placa con microcontrolador, un entorno de desarrollo (el IDE) y una comunidad enorme. Sirve para leer sensores, encender LEDs, mover motores, mostrar datos en pantallas y conectar proyectos a internet.

Programas en un lenguaje basado en C/C++. Cada programa se llama sketch y se guarda en un archivo .ino. Lo escribes en el PC, lo subes a la placa por USB y la placa lo ejecuta sola (sin necesidad de dejar el PC conectado).

Qué puedes hacer con él

  • Proyectos educativos: semáforos, alarmas, termómetros, robots sencillos.
  • Automatización en casa: luces, riego, detectores de movimiento.
  • Medición: temperatura, humedad, distancia, luz, calidad del aire.
  • Con placas como ESP32: WiFi, Bluetooth y proyectos IoT.

Si estás empezando

Compra un Arduino Uno (oficial o compatible) y un kit de iniciación con protoboard, LEDs, resistencias, potenciómetro, botón, cables jumpers y algún sensor. Casi todos los ejemplos de esta guía asumen Uno a 5 V.

ESP32 y 5 V

Los pines del ESP32 son de 3,3 V. No les conectes señales de 5 V directamente. Usa divisores de tensión o convertidores de nivel cuando hables con módulos a 5 V.

  3. Entradas/salidas, sensores, motores, pantallas y librerías.
  4. Temporización con millis(), comunicación y errores frecuentes.

Instalar Arduino IDE

El Arduino IDE es el programa donde escribes el sketch, lo verificas (compilas) y lo subes a la placa. En Windows conviene la versión 2.x (más moderna) o la 1.8.x (más ligera). Ambas sirven para esta guía.

1. Descargar e instalar

  1. Entra en arduino.cc/en/software.
  2. Descarga el instalador para Windows (o el ZIP si no quieres instalar).
  3. Ejecuta el instalador. Acepta instalar los drivers USB cuando te lo pida.
  4. Al terminar, abre Arduino IDE.
También con winget

Si tienes Windows reciente:

winget install --id ArduinoSA.IDE.stable -e

2. Conectar la placa por USB

  • Usa un cable de datos (algunos cables solo cargan y no transmiten).
  • Conecta la placa al PC. Debe encenderse un LED de alimentación (ON / PWR).
  • Windows debería detectar un puerto COM (por ejemplo COM3).

3. Drivers (si el puerto no aparece)

Chip USB de la placaQué instalar
ATmega16U2 (Uno/Mega oficiales)Suele venir con el instalador de Arduino.
CH340 / CH341 (muchos clones)Driver CH340 de WCH; reinicia el PC si hace falta.
CP210x (algunos Nano y ESP32)Driver Silicon Labs CP210x.
FTDIDriver FTDI VCP.

Para ver el puerto: clic derecho en el menú Inicio → Administrador de dispositivos → Puertos (COM y LPT). Si ves un dispositivo con signo de admiración, falta el driver.

Descarga drivers solo de sitios conocidos

Busca el fabricante (WCH, Silicon Labs, FTDI) o la documentación de tu placa. Evita “paquetes todo en uno” de sitios dudosos.

4. Primera comprobación en el IDE

  1. Herramientas → Placa y elige tu modelo (p. ej. Arduino Uno).
  2. Herramientas → Puerto y elige el COMx que apareció al conectar.
  3. Abre el ejemplo Blink: Archivo → Ejemplos → 01.Basics → Blink.
  4. Pulsa el botón de Subir (flecha). Si termina sin error, la instalación está bien.

Conocer el Arduino IDE

Conocer cuatro controles te basta para el día a día: verificar, subir, elegir placa/puerto y abrir el monitor serie.

Placa y puerto

  • Herramientas → Placa: debe coincidir con lo que tienes enchufado (o el perfil correcto del ESP32).
  • Herramientas → Puerto: el COM de tu placa. Si no hay ninguno, revisa cable y drivers.
  • En IDE 2.x también puedes elegir placa y puerto en el selector de la barra inferior / superior.
Procesador en Nano antiguos

Algunos Nano necesitan Herramientas → Procesador → ATmega328P (Old Bootloader) si el subido falla con “not in sync”.

Área de mensajes

Debajo del editor aparece la consola: progreso de compilación, tamaño del programa y errores. Si falla al subir, lee la última línea: suele decir si el problema es el puerto, la placa o el sketch.

Preferencias útiles

  • Archivo → Preferencias: marca “Mostrar salida detallada al subir” cuando depuras un fallo de conexión.
  • Anota la carpeta de sketches (por defecto Documentos\Arduino).
Orden típico cada vez que conectas

1) Cable USB → 2) elegir placa → 3) elegir puerto → 4) Verificar → 5) Subir → 6) abrir Monitor serie si el sketch imprime algo.

Electrónica básica y seguridad

No hace falta ser ingeniero, pero sí respetar voltaje, corriente y polaridad. Un cable mal puesto puede quemar un pin o un módulo.

Voltaje, corriente y resistencia

ConceptoEn la práctica
Voltaje (V)“Presión” eléctrica. Arduino Uno trabaja a 5 V. ESP32 a 3,3 V.
Corriente (A / mA)Cuánta carga fluye. Un pin digital del Uno aguanta ~20 mA de forma segura (mejor no pasarse).
Resistencia (Ω)Limita la corriente. Un LED siempre lleva resistencia en serie.

Ley de Ohm (idea): V = I × R. Para un LED rojo a 5 V, una resistencia de 220 Ω o 330 Ω suele ir bien.

Protoboard

La protoboard permite montar circuitos sin soldar:

  • Los agujeros de cada fila corta (en la zona central) están unidos entre sí.
  • El “canal” central separa las dos mitades: un circuito integrado se coloca a caballo.
  • Las líneas laterales (buses +/−) suelen llevar 5 V y GND a lo largo de la placa.

Pines importantes del Uno

  • 5V y 3.3V: alimentación para módulos (no abuses de la corriente).
  • GND: tierra común. Todos los GND del circuito deben unirse.
  • 0–13: digitales. El 13 suele tener un LED en la placa.
  • A0–A5: entradas analógicas (también se pueden usar como digitales).
  • VIN: alimentación externa (p. ej. 7–12 V). El regulador de la placa genera los 5 V.

Seguridad

Nunca conectes 220 V / red eléctrica a Arduino

Para bombillas o electrodomésticos usa un relé o un módulo adecuado, con aislamiento, y solo si sabes lo que haces. La red eléctrica puede matar.

Reglas de oro
  • Desconecta el USB (o la alimentación) antes de cambiar cables.
  • No cortocircuites 5 V con GND.
  • Respeta la polaridad de LEDs, electrolíticos y módulos.
  • Motores y servos “grandes” necesitan alimentación aparte; solo compartes GND con Arduino.
  • No saques de un pin más corriente de la recomendada: usa transistor, MOSFET o driver.
Multímetro

Con uno barato mides si hay 5 V, continuidad en cables y el valor de una resistencia. Es la herramienta que más tiempo te ahorra al depurar un circuito.

Estructura de un sketch

Todo sketch de Arduino tiene al menos dos funciones especiales: setup() y loop(). El microcontrolador las llama automáticamente.

Esqueleto mínimo

void setup() {
  // Se ejecuta UNA vez al encender o al reset
}

void loop() {
  // Se ejecuta una y otra vez, para siempre
}

Orden de ejecución

  1. Alimentas la placa (USB o externa) o pulsas RESET.
  2. Se ejecuta setup() una sola vez: aquí configuras pines, Serial, sensores…
  3. Entra en loop() y lo repite sin parar hasta que apagues o reinicies.
void setup() {
  Serial.begin(9600);
  Serial.println("Arranque: setup terminado");
}

void loop() {
  Serial.println("Paso por loop");
  delay(1000);  // espera 1 segundo (bloquea; más adelante verás millis)
}

Variables globales y constantes

Lo que declares fuera de las funciones es global (accesible desde setup y loop). Usa const para pines fijos:

const int PIN_LED = 13;

void setup() {
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  digitalWrite(PIN_LED, HIGH);
  delay(500);
  digitalWrite(PIN_LED, LOW);
  delay(500);
}
Tipos habituales

int, long, float, bool, char, byte, String (objeto de Arduino). Para tiempos con millis() conviene unsigned long.

Comentarios

Igual que en C++: // una línea y /* ... */ varias. Explica el porqué (pin, cableado, unidad del sensor).

Tu primer proyecto: LED parpadeante

El “Hola, mundo” de Arduino: un LED que enciende y apaga. Practicas pinMode, digitalWrite y delay.

Material

  • Arduino Uno (o compatible).
  • 1 LED (cualquier color).
  • 1 resistencia 220 Ω o 330 Ω.
  • Protoboard y cables jumpers.

Cableado

  1. Pata larga del LED (ánodo, +) → resistencia → pin digital 8 (o el que elijas).
  2. Pata corta del LED (cátodo, −) → GND.
Sin resistencia, el LED (o el pin) puede dañarse

La resistencia limita la corriente. No la omitas “para probar un segundo”.

Sketch

const int PIN_LED = 8;

void setup() {
  pinMode(PIN_LED, OUTPUT);  // el pin será salida
}

void loop() {
  digitalWrite(PIN_LED, HIGH);  // 5 V → LED encendido
  delay(1000);                 // espera 1000 ms = 1 s
  digitalWrite(PIN_LED, LOW);   // 0 V → LED apagado
  delay(1000);
}

Qué hace cada función

FunciónPara qué
pinMode(pin, OUTPUT)Configura el pin como salida.
digitalWrite(pin, HIGH/LOW)Pone el pin a alto (≈5 V) o bajo (0 V).
delay(ms)Pausa el programa ese número de milisegundos. Mientras tanto no hace nada más.

Atajo: LED integrado

El pin 13 del Uno tiene un LED en la propia placa. Puedes probar sin protoboard:

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
  delay(200);
  digitalWrite(LED_BUILTIN, LOW);
  delay(200);
}
Si no parpadea

Revisa polaridad del LED, que el pin del código coincida con el cable, que hayas subido el sketch y que la placa tenga alimentación.

  3. Elige la velocidad: 9600 debe coincidir con Serial.begin(9600).

Si ves símbolos raros, el baud rate del monitor no coincide con el del sketch. Cámbialo a 9600 (o al valor que usaste).

Leer lo que escribes en el monitor

void setup() {
  Serial.begin(9600);
  pinMode(LED_BUILTIN, OUTPUT);
  Serial.println("Escribe 1 para encender, 0 para apagar");
}

void loop() {
  if (Serial.available() > 0) {
    char c = Serial.read();
    if (c == '1') {
      digitalWrite(LED_BUILTIN, HIGH);
      Serial.println("LED ON");
    } else if (c == '0') {
      digitalWrite(LED_BUILTIN, LOW);
      Serial.println("LED OFF");
    }
  }
}
Consejo de depuración

Cuando algo “no funciona”, imprime el valor que lees del sensor o del botón antes de cambiar el cableado otra vez. Muchas veces el circuito está bien y la lógica no.

Entradas y salidas digitales

Un pin digital solo conoce dos estados: HIGH o LOW. Como salida enciende cosas; como entrada lee botones e interruptores.

Salida: repaso rápido

pinMode(8, OUTPUT);
digitalWrite(8, HIGH);  // activo
digitalWrite(8, LOW);   // inactivo

Entrada con botón y pull-up interno

Lo más sencillo y fiable: un botón entre el pin y GND, y activar la resistencia de pull-up interna con INPUT_PULLUP. Así el pin lee HIGH en reposo y LOW al pulsar.

Cableado: un extremo del botón al pin 2, el otro a GND. No hace falta resistencia externa.

const int PIN_BOTON = 2;
const int PIN_LED = 8;

void setup() {
  pinMode(PIN_BOTON, INPUT_PULLUP);
  pinMode(PIN_LED, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int estado = digitalRead(PIN_BOTON);  // LOW = pulsado
  if (estado == LOW) {
    digitalWrite(PIN_LED, HIGH);
    Serial.println("Pulsado");
  } else {
    digitalWrite(PIN_LED, LOW);
  }
}

Antirrebote (debounce)

Al pulsar, el contacto mecánico “rebota” y puede generar varios flancos. Una espera corta tras detectar el cambio suele bastar:

const int PIN_BOTON = 2;
bool ledEncendido = false;
int lecturaAnterior = HIGH;

void setup() {
  pinMode(PIN_BOTON, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  int lectura = digitalRead(PIN_BOTON);
  if (lectura == LOW && lecturaAnterior == HIGH) {
    delay(30);  // antirrebote simple
    if (digitalRead(PIN_BOTON) == LOW) {
      ledEncendido = !ledEncendido;
      digitalWrite(LED_BUILTIN, ledEncendido ? HIGH : LOW);
    }
  }
  lecturaAnterior = lectura;
}
Pull-down externo

También puedes poner el botón entre 5 V y el pin, y una resistencia (10 kΩ) del pin a GND (pull-down). Entonces reposo = LOW y pulsado = HIGH. Con INPUT_PULLUP te ahorras esa resistencia.

No dejes un INPUT “flotando”

Si configuras INPUT sin pull-up/down, el pin capta ruido y el valor salta solo. Usa INPUT_PULLUP o una resistencia externa.

Entradas analógicas

analogRead mide un voltaje entre 0 y 5 V (en el Uno) y lo convierte a un número entero de 0 a 1023 (ADC de 10 bits).

Potenciómetro

Un potenciómetro es un divisor de tensión ajustable. Tres patas: una a 5 V, otra a GND, y la central (cursor) a A0.

void setup() {
  Serial.begin(9600);
}

void loop() {
  int crudo = analogRead(A0);          // 0..1023
  float voltios = crudo * (5.0 / 1023.0);
  Serial.print("ADC: ");
  Serial.print(crudo);
  Serial.print("  V: ");
  Serial.println(voltios);
  delay(200);
}

ADC: 512  V: 2.50
ADC: 1023  V: 5.00

map(): convertir rangos

map(valor, deMin, deMax, aMin, aMax) reescala un número. Útil para pasar de 0–1023 a 0–255 (PWM) o a un ángulo 0–180 (servo):

void setup() {
  Serial.begin(9600);
}

void loop() {
  int crudo = analogRead(A0);
  int brillo = map(crudo, 0, 1023, 0, 255);
  int angulo = map(crudo, 0, 1023, 0, 180);
  Serial.print(brillo);
  Serial.print(" / ");
  Serial.println(angulo);
  delay(100);
}
map usa enteros

No redondea con decimales. Para cálculos finos, haz la regla de tres con float a mano.

ESP32

En ESP32 el ADC suele ir de 0 a 4095 (12 bits) y la referencia es 3,3 V. Ajusta las fórmulas.

Salidas PWM

PWM (modulación por ancho de pulso) simula un voltaje intermedio encendiendo y apagando muy rápido. En Arduino usas analogWrite(pin, valor) con valor de 0 a 255.

Pines PWM del Uno

Solo algunos pines digitales soportan PWM: 3, 5, 6, 9, 10 y 11 (marcados con ~ en la serigrafía).

Brillo de un LED

LED + resistencia en el pin 9, cátodo a GND. Potenciómetro en A0 (opcional):

const int PIN_PWM = 9;

void setup() {
  // analogWrite no necesita pinMode en la mayoría de placas AVR, pero no estorba:
  pinMode(PIN_PWM, OUTPUT);
}

void loop() {
  int crudo = analogRead(A0);
  int brillo = map(crudo, 0, 1023, 0, 255);
  analogWrite(PIN_PWM, brillo);
  delay(10);
}

Fundido automático

const int PIN_PWM = 9;

void setup() {
  pinMode(PIN_PWM, OUTPUT);
}

void loop() {
  for (int v = 0; v <= 255; v++) {
    analogWrite(PIN_PWM, v);
    delay(8);
  }
  for (int v = 255; v >= 0; v--) {
    analogWrite(PIN_PWM, v);
    delay(8);
  }
}

Velocidad de un motor DC (idea)

No conectes un motor directo al pin. Usa un driver (L298N, TB6612…) y alimenta el motor aparte. El pin PWM del Arduino solo manda la señal de velocidad al driver.

analogWrite no es “analógico de verdad”

Sigue siendo digital pulsado. Un voltímetro puede mostrar un promedio; un LED lo percibe como brillo continuo.

En ESP32 la API cambia

En muchos cores de ESP32 se usa el API de LEDC en lugar del analogWrite clásico. Revisa el ejemplo de tu placa.

Sensores más comunes

Cuatro sensores que aparecen en casi todos los kits. Instala las librerías que indiquen (sección Librerías) cuando haga falta.

DHT11 — temperatura y humedad

Pines típicos del módulo: VCC→5 V, GND→GND, DATA→pin 4 (a veces con resistencia pull-up ya soldada).

#include <DHT.h>

#define PIN_DHT 4
#define TIPO_DHT DHT11

DHT dht(PIN_DHT, TIPO_DHT);

void setup() {
  Serial.begin(9600);
  dht.begin();
}

void loop() {
  float h = dht.readHumidity();
  float t = dht.readTemperature();  // °C

  if (isnan(h) || isnan(t)) {
    Serial.println("Error leyendo DHT11");
    return;
  }

  Serial.print("Humedad: ");
  Serial.print(h);
  Serial.print("%  Temp: ");
  Serial.print(t);
  Serial.println(" C");
  delay(2000);  // el DHT11 no quiere lecturas demasiado seguidas
}

HC-SR04 — distancia ultrasónica

VCC→5 V, GND→GND, TRIG→pin 9, ECHO→pin 10.

const int PIN_TRIG = 9;
const int PIN_ECHO = 10;

void setup() {
  Serial.begin(9600);
  pinMode(PIN_TRIG, OUTPUT);
  pinMode(PIN_ECHO, INPUT);
}

void loop() {
  digitalWrite(PIN_TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(PIN_TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(PIN_TRIG, LOW);

  long duracion = pulseIn(PIN_ECHO, HIGH);  // µs
  float cm = duracion * 0.0343 / 2.0;

  Serial.print("Distancia: ");
  Serial.print(cm);
  Serial.println(" cm");
  delay(200);
}
ECHO a 5 V en ESP32

El eco del HC-SR04 suele ser a 5 V. En ESP32 usa un divisor de resistencia o un módulo compatible con 3,3 V.

LDR — sensor de luz

La LDR cambia su resistencia con la luz. Montaje típico: 5 V → LDR → nodo → resistencia 10 kΩ → GND. El nodo va a A0.

void setup() {
  Serial.begin(9600);
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  int luz = analogRead(A0);  // valores altos o bajos según el montaje
  Serial.println(luz);
  digitalWrite(LED_BUILTIN, luz < 400 ? HIGH : LOW);  // umbral de ejemplo
  delay(100);
}

PIR — detector de movimiento

Módulos HC-SR501: VCC, GND y OUT a un pin digital. OUT pasa a HIGH cuando detecta movimiento (tras un tiempo de estabilización al encender).

const int PIN_PIR = 7;

void setup() {
  Serial.begin(9600);
  pinMode(PIN_PIR, INPUT);
  pinMode(LED_BUILTIN, OUTPUT);
  Serial.println("Calentando PIR (aprox. 30 s)...");
  delay(30000);
}

void loop() {
  bool movimiento = digitalRead(PIN_PIR) == HIGH;
  digitalWrite(LED_BUILTIN, movimiento ? HIGH : LOW);
  if (movimiento) {
    Serial.println("Movimiento detectado");
  }
  delay(50);
}
Calibra umbrales con el monitor serie

Imprime los valores crudos unos minutos y decide qué número significa “oscuro”, “cerca” o “alarma”. Cada montaje es distinto.

Motores, servos y relés

Los actuadores convierten señales en movimiento o conmutación. Casi siempre necesitan más corriente de la que un pin puede dar: usa drivers y alimentación adecuada.

Servo SG90

Cableado típico: rojo→5 V, marrón/negro→GND, naranja/amarillo→pin 9 (señal). Para varios servos, alimenta a 5 V externos y une GND con Arduino.

#include <Servo.h>

Servo miServo;

void setup() {
  miServo.attach(9);
}

void loop() {
  miServo.write(0);
  delay(1000);
  miServo.write(90);
  delay(1000);
  miServo.write(180);
  delay(1000);
}

Motor DC con L298N

El L298N recibe alimentación del motor (p. ej. 6–12 V en el bornes del módulo), GND común con Arduino, y señales IN1/IN2 (dirección) + ENA (PWM de velocidad).

const int IN1 = 8;
const int IN2 = 7;
const int ENA = 9;  // PWM

void setup() {
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
  pinMode(ENA, OUTPUT);
}

void adelante(int velocidad) {
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, LOW);
  analogWrite(ENA, velocidad);  // 0..255
}

void atras(int velocidad) {
  digitalWrite(IN1, LOW);
  digitalWrite(IN2, HIGH);
  analogWrite(ENA, velocidad);
}

void parar() {
  digitalWrite(IN1, LOW);
  digitalWrite(IN2, LOW);
  analogWrite(ENA, 0);
}

void loop() {
  adelante(180);
  delay(1500);
  parar();
  delay(500);
  atras(180);
  delay(1500);
  parar();
  delay(1000);
}
Alimentación de motores

No alimentes motores medianos/grandes solo desde el 5 V del USB. Usa batería o fuente aparte y GND común. Sin eso reiniciarás la placa o quemarás el regulador.

Relé

Un módulo de relé aísla (ópticamente en muchos kits) una carga de más voltaje. El pin IN se controla con digitalWrite. Lee la serigrafía: algunos se activan en LOW.

const int PIN_RELE = 6;

void setup() {
  pinMode(PIN_RELE, OUTPUT);
  digitalWrite(PIN_RELE, HIGH);  // muchos módulos: HIGH = apagado
}

void loop() {
  digitalWrite(PIN_RELE, LOW);   // activa
  delay(2000);
  digitalWrite(PIN_RELE, HIGH);  // desactiva
  delay(2000);
}
Cargas de red (220 V)

Si no tienes formación en electricidad, no manipules la red. Usa bombillas de baja tensión o lámparas USB para practicar.

Buzzer

Buzzer activo: HIGH/LOW como un LED. Buzzer pasivo: usa tone(pin, frecuencia) / noTone(pin).

const int PIN_BUZZER = 5;

void setup() {
  pinMode(PIN_BUZZER, OUTPUT);
}

void loop() {
  tone(PIN_BUZZER, 1000);  // 1 kHz
  delay(300);
  noTone(PIN_BUZZER);
  delay(700);
}

Pantallas LCD y OLED

Mostrar texto evita depender del PC. Las opciones más amigables al empezar son el LCD 16×2 con backpack I2C y las OLED SSD1306 también por I2C.

LCD 16×2 I2C

Cableado: VCC→5 V, GND→GND, SDA→A4, SCL→A5 (en el Uno). Instala la librería LiquidCrystal I2C (o similar) desde el gestor.

#include <Wire.h>
#include <LiquidCrystal_I2C.h>

// Dirección frecuente: 0x27 o 0x3F (escanea si no ves nada)
LiquidCrystal_I2C lcd(0x27, 16, 2);

void setup() {
  lcd.init();
  lcd.backlight();
  lcd.setCursor(0, 0);
  lcd.print("Hola, Arduino");
  lcd.setCursor(0, 1);
  lcd.print("Gia para prog.");
}

void loop() {
  // nada: el texto permanece
}
Pantalla en blanco

Prueba la otra dirección I2C (0x3F), sube el contraste del potenciómetro del backpack y verifica SDA/SCL. Un sketch “I2C scanner” lista las direcciones presentes.

OLED 128×64 (SSD1306)

Suele ir a 3,3–5 V según el módulo. Librerías habituales: Adafruit SSD1306 + Adafruit GFX, o U8g2.

#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

#define ANCHO 128
#define ALTO 64
Adafruit_SSD1306 display(ANCHO, ALTO, &Wire, -1);

void setup() {
  if (!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    for (;;) { /* no se encontró la pantalla */ }
  }
  display.clearDisplay();
  display.setTextSize(1);
  display.setTextColor(SSD1306_WHITE);
  display.setCursor(0, 0);
  display.println("OLED lista");
  display.display();  // ¡imprescindible para volcar el buffer!
}

void loop() {
  display.clearDisplay();
  display.setCursor(0, 20);
  display.print("ms: ");
  display.println(millis());
  display.display();
  delay(200);
}
I2C en Uno

SDA = A4, SCL = A5. En Mega son pines distintos (20 y 21). En ESP32 suelen ser configurables; muchos kits usan 21 (SDA) y 22 (SCL).

Librerías

Una librería añade funciones listas (sensores, pantallas, WiFi…). Evita reinventar protocolos complicados.

Instalar desde el gestor

  1. Herramientas → Administrar bibliotecas… (IDE 1.x: Programa → Incluir librería → Administrar bibliotecas).
  2. Busca el nombre (p. ej. DHT sensor library, Servo ya viene incluida).
  3. Instala y cierra el gestor.
  4. En el sketch: #include <Nombre.h>.

Ejemplo de uso

#include <Servo.h>   // cabecera de la librería

Servo brazo;          // objeto que expone la librería

void setup() {
  brazo.attach(9);    // métodos del objeto
}

void loop() {
  brazo.write(90);
  delay(500);
}

Dónde se guardan

  • Librerías del usuario: carpeta Documentos\Arduino\libraries.
  • Cada librería es una carpeta con sus .h / .cpp.
  • Tras instalar a mano (ZIP), reinicia el IDE.
Conflictos de nombres

No metas dos librerías distintas con el mismo nombre de carpeta. Si un ejemplo no compila, lee el error: a menudo falta una dependencia (p. ej. Adafruit GFX junto a SSD1306).

Ejemplos incluidos

Archivo → Ejemplos lista demos de las librerías instaladas. Es la forma más rápida de comprobar cableado y dirección I2C.

millis(): hacer varias cosas a la vez

delay() es fácil, pero bloquea: mientras esperas, no lees botones ni actualizas pantallas. millis() devuelve los milisegundos desde el arranque y te deja programar esperas sin frenar el resto.

Patrón básico

const int PIN_LED = 8;
unsigned long anterior = 0;
const unsigned long INTERVALO = 500;  // ms
bool encendido = false;

void setup() {
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  unsigned long ahora = millis();
  if (ahora - anterior >= INTERVALO) {
    anterior = ahora;
    encendido = !encendido;
    digitalWrite(PIN_LED, encendido ? HIGH : LOW);
  }

  // aquí puedes leer botones, sensores, etc. en cada vuelta
}

Dos LEDs a ritmos distintos

const int LED_A = 8;
const int LED_B = 9;

unsigned long tA = 0, tB = 0;
bool estadoA = false, estadoB = false;

void setup() {
  pinMode(LED_A, OUTPUT);
  pinMode(LED_B, OUTPUT);
}

void loop() {
  unsigned long ahora = millis();

  if (ahora - tA >= 500) {
    tA = ahora;
    estadoA = !estadoA;
    digitalWrite(LED_A, estadoA);
  }

  if (ahora - tB >= 200) {
    tB = ahora;
    estadoB = !estadoB;
    digitalWrite(LED_B, estadoB);
  }
}
Por qué restar y no comparar absolutos

Usar ahora - anterior >= INTERVALO funciona incluso cuando millis() desborda (~49 días) y vuelve a cero, si las variables son unsigned long.

Cuándo sí usar delay

En demos cortas, esperas de sensores (DHT) o pulsos de microsegundos (delayMicroseconds) está bien. En proyectos interactivos, prefiere millis().

Comunicación: Serial, I2C y SPI

Las placas y módulos “hablan” por buses. No necesitas memorizar los protocolos: sí saber cuál usa tu sensor y qué pines toca.

Resumen

BusHilos típicosUso frecuente
UART / SerialTX, RX (+ GND)Monitor serie, GPS, Bluetooth HC-05, comunicación entre placas.
I2CSDA, SCL (+ VCC, GND)LCD I2C, OLED, RTC, muchos sensores. Varios dispositivos, dos cables de datos.
SPIMOSI, MISO, SCK, CSPantallas rápidas, tarjetas SD, algunos sensores. Más cables, más velocidad.

Serial (UART)

Ya lo usaste con Serial. En el Uno, los pines 0 (RX) y 1 (TX) son el mismo canal USB: si conectas un módulo ahí, desconéctalo al subir el sketch o usa SoftwareSerial en otros pines.

I2C

Cada dispositivo tiene una dirección (p. ej. 0x27, 0x3C). Librería base: Wire.h. No mezcles dispositivos a 5 V y 3,3 V sin nivelación.

SPI

En Uno: 11 MOSI, 12 MISO, 13 SCK y un CS por dispositivo (p. ej. 10). Suele ir con librerías específicas del módulo.

Bluetooth (HC-05 / HC-06) — breve

Módulo serie inalámbrico: VCC, GND, TXD→RX de Arduino, RXD→TX (a veces con divisor 5 V→3,3 V). Emparejas el móvil o el PC y envías los mismos caracteres que por el monitor serie.

WiFi — breve

Con ESP32 o ESP8266 usas WiFi integrado y librerías como WiFi.h para conectarte a tu red, montar un servidor web sencillo o publicar datos. El Uno clásico necesita un shield o módulo externo (ESP-01, Ethernet…).

No subas contraseñas a repositorios públicos

Si publicas un sketch con SSID y password, cámbialos o usa un archivo local que no subas a GitHub.

Errores comunes y cómo resolverlos

La mayoría de fallos al empezar son de cable, puerto o placa mal seleccionada, no del código.

Tabla rápida

SíntomaQué probar
No aparece puerto COMCable de datos, otro USB, drivers CH340/CP210x, Administrador de dispositivos.
port not found / no se puede abrir el puertoCierra el monitor serie, cierra otros programas que usen el COM, vuelve a elegir puerto.
avrdude: stk500_getsync(): not in syncPlaca/puerto incorrectos; pulsa RESET al subir; Nano con “Old Bootloader”; cable flojo.
Sube bien pero no hace lo esperadoPin del código ≠ pin del cable; falta GND común; LED al revés; abre Serial y depura.
Compila con error de libreríaInstala la librería; revisa el #include; mayúsculas en el nombre del .h.
Pantalla I2C en blancoDirección 0x27 vs 0x3F; SDA/SCL; alimentación; contraste.
La placa se reinicia al mover un motorAlimentación insuficiente; motor con fuente aparte + GND común; condensador de desacople.
Caracteres raros en el monitorBaud rate distinto (9600 vs 115200).

“not in sync” paso a paso

  1. Confirma Placa exacta (Uno ≠ Nano ≠ Mega).
  2. Confirma Puerto (desconecta y mira cuál desaparece).
  3. Cierra el monitor serie e intenta de nuevo.
  4. Prueba otro cable USB.
  5. En Nano clon: Procesador → ATmega328P (Old Bootloader).
Salida detallada

En Preferencias activa la salida detallada al subir. El final del log suele señalar si avrdude encontró el puerto o falló el protocolo.

ESP32: “Failed to connect”

Mantén pulsado BOOT (y a veces EN) según tu placa mientras empieza la carga, o usa un cable de datos de calidad. Instala el soporte ESP32 desde el gestor de placas.

Proyectos para practicar

Ideas concretas para juntar lo aprendido. Empieza por el cableado, imprime valores por Serial y luego añade la lógica.

1. Semáforo peatonal

  • Material: 3 LEDs (rojo, amarillo, verde) + resistencias; opcional botón peatón.
  • Lógica: secuencia verde → amarillo → rojo con delay o mejor con millis.
  • Extra: al pulsar el botón, acelera el cambio a rojo para el coche / verde peatón.

2. Alarma con PIR y buzzer

  • Material: PIR, buzzer, LED.
  • Lógica: si PIR = HIGH, suena tone y enciende LED durante N segundos.
  • Extra: botón para armar/desarmar; mensaje por Serial.
const int PIN_PIR = 7;
const int PIN_BUZZER = 5;
const int PIN_LED = 8;

void setup() {
  pinMode(PIN_PIR, INPUT);
  pinMode(PIN_BUZZER, OUTPUT);
  pinMode(PIN_LED, OUTPUT);
  delay(30000);  // calentamiento PIR
}

void loop() {
  if (digitalRead(PIN_PIR) == HIGH) {
    digitalWrite(PIN_LED, HIGH);
    tone(PIN_BUZZER, 2000);
    delay(2000);
    noTone(PIN_BUZZER);
    digitalWrite(PIN_LED, LOW);
  }
}

3. Termómetro con DHT11 y LCD

  • Lee temperatura/humedad cada 2 s.
  • Muéstralas en LCD I2C (línea 1: temp, línea 2: humedad).
  • Si temperatura > umbral, enciende un LED de aviso.

4. Medidor de distancia

  • HC-SR04 + LED o buzzer que pite más rápido cuanto más cerca (como sensor de aparcamiento).
  • Usa millis para el ritmo del pitido sin bloquear la medición.

5. Luz automática con LDR

  • Si analogRead indica oscuridad, analogWrite sube el brillo de un LED (PWM).
  • Ajusta el umbral mirando el monitor serie de noche y de día.

6. Control de servo con potenciómetro

#include <Servo.h>

Servo servo;
void setup() {
  servo.attach(9);
}

void loop() {
  int angulo = map(analogRead(A0), 0, 1023, 0, 180);
  servo.write(angulo);
  delay(15);
}

Orden sugerido

  1. LED + botón (digital).
  2. Potenciómetro + PWM.
  3. Un sensor (LDR o HC-SR04) con Serial.
  4. Pantalla o servo.
  5. Proyecto “completo” (alarma o termómetro) con millis.
Cómo practicar sin frustrarte

Cambia una sola cosa cada vez (un cable o tres líneas de código). Si se rompe, vuelve al último sketch que funcionaba. Guarda versiones con nombres claros: semaforo_v1, semaforo_boton.
