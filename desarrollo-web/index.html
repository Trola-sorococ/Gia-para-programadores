Estructura de una página HTML

HTML describe qué hay en la página: títulos, párrafos, imágenes, enlaces. El navegador lee el archivo, arma el documento y luego aplica el CSS (cómo se ve) y el JavaScript (cómo reacciona).

Documento mínimo

Crea una carpeta, por ejemplo mi-sitio, y dentro un archivo index.html:

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi primera página</title>
</head>
<body>
  <h1>Hola, mundo</h1>
  <p>Esta es mi primera página web.</p>
</body>
</html>

Ábrelo con doble clic o arrástralo al navegador. Deberías ver el título grande y el párrafo debajo.

Qué hace cada pieza

PartePara qué sirve
<!DOCTYPE html>Dice al navegador que es HTML5 (modo estándar).
<html lang="es">Raíz del documento. lang ayuda a lectores de pantalla y a la traducción.
<head>Metadatos: charset, viewport, título, CSS, favicon. No se ve en la página.
<meta charset="utf-8">Permite acentos y eñes sin caracteres raros.
viewportHace que el ancho se adapte al celular. Sin esto, el móvil “simula” una pantalla grande.
<title>Texto de la pestaña del navegador y de los favoritos.
<body>Todo el contenido visible: textos, imágenes, formularios.

Etiquetas básicas de texto

<h1>Título principal (uno por página)</h1>
<h2>Sección</h2>
<h3>Subsección</h3>

<p>Un párrafo con <strong>énfasis fuerte</strong>
y <em>énfasis suave</em>.</p>

<ul>
  <li>Lista sin orden</li>
  <li>Otro ítem</li>
</ul>

<ol>
  <li>Paso uno</li>
  <li>Paso dos</li>
</ol>

<!-- Esto es un comentario: el navegador lo ignora -->
Jerarquía de títulos

Usa un solo <h1> por página. Luego h2, h3… sin saltar niveles (no pases de h2 a h4). Ayuda a la accesibilidad y al SEO.

Cómo se anidan las etiquetas

Las etiquetas se abren y se cierran como cajas dentro de cajas. El cierre va en orden inverso:

<p>Texto con <strong>negrita</strong> y listo.</p>
<p>Texto con <strong>negrita</p></strong>
Algunas etiquetas no se cierran

<img>, <br>, <hr>, <meta> e <input> son vacías: no tienen contenido ni etiqueta de cierre.

HTML semántico y formularios

Semántico significa usar etiquetas que describen el significado, no solo la apariencia. Así la página es más clara para humanos, buscadores y lectores de pantalla.

Esqueleto semántico típico

<body>
  <header>
    <a href="/">Mi marca</a>
    <nav>
      <a href="#servicios">Servicios</a>
      <a href="#contacto">Contacto</a>
    </nav>
  </header>

  <main>
    <section id="servicios">
      <h2>Servicios</h2>
      <article>
        <h3>Diseño web</h3>
        <p>Páginas claras y rápidas.</p>
      </article>
    </section>

    <section id="contacto">
      <h2>Contacto</h2>
      <!-- formulario abajo -->
    </section>
  </main>

  <footer>
    <p>&copy; 2026 Mi marca</p>
  </footer>
</body>
EtiquetaCuándo usarla
<header>Cabecera de la página o de un bloque (logo, nav).
<nav>Conjunto de enlaces de navegación principales.
<main>Contenido único de la página (uno por documento).
<section>Bloque temático con su propio encabezado.
<article>Contenido que tiene sentido solo (post, tarjeta, noticia).
<aside>Contenido relacionado pero secundario (barra lateral).
<footer>Pie: copyright, enlaces legales, redes.

Enlaces e imágenes

<!-- Enlace interno (ancla) y externo -->
<a href="#contacto">Ir a contacto</a>
<a href="https://ejemplo.com" target="_blank" rel="noopener">
  Sitio externo
</a>

<!-- Imagen: alt describe la imagen si no se ve -->
<img src="foto.jpg" alt="Escritorio con laptop y café" width="800" height="500">
target="_blank" y rel="noopener"

Al abrir otra pestaña, añade rel="noopener" (o noopener noreferrer) por seguridad. El alt de las imágenes no es opcional: si la imagen es decorativa, usa alt="".

Formulario de contacto

<form action="/enviar" method="post">
  <label for="nombre">Nombre</label>
  <input id="nombre" name="nombre" type="text" required autocomplete="name">

  <label for="email">Correo</label>
  <input id="email" name="email" type="email" required autocomplete="email">

  <label for="mensaje">Mensaje</label>
  <textarea id="mensaje" name="mensaje" rows="4" required></textarea>

  <label>
    <input type="checkbox" name="acepto" required>
    Acepto la política de privacidad
  </label>

  <button type="submit">Enviar</button>
</form>
typeUso
textTexto libre (nombre, asunto).
emailValida formato de correo en el navegador.
passwordOculta lo que escribes.
number / telNúmeros o teléfono.
checkbox / radioOpciones (varias / una sola).
fileSubir archivos.
submit (en button)Envía el formulario.
label + for + id

Conecta cada <label for="..."> con el id del campo. Así puedes hacer clic en el texto para enfocar el input, y los lectores de pantalla anuncian bien el campo.

action necesita un servidor

Sin backend, action no “envía” a nadie. Para practicar el HTML basta; para producción usarás un servicio de formularios, una API o JavaScript con fetch.

CSS: conectarlo y selectores

CSS describe cómo se ve el HTML: colores, tamaños, layout. La forma profesional es un archivo aparte.

Enlazar la hoja de estilos

<head>
  <meta charset="utf-8">
  <title>Mi sitio</title>
  <link rel="stylesheet" href="estilos.css">
</head>
body {
  font-family: system-ui, sans-serif;
  margin: 0;
  line-height: 1.6;
  color: #1a1a1a;
  background: #f7f7f5;
}

h1 {
  font-size: 2rem;
  color: #0f172a;
}
Tres formas de aplicar CSS

1) Archivo externo (<link>) — la recomendada. 2) <style> en el head — útil para prototipos cortos. 3) Atributo style="" en la etiqueta — evita usarlo salvo casos muy puntuales.

Selectores: a quién le hablas

/* Por etiqueta */
p { margin-bottom: 1rem; }

/* Por clase (reutilizable) */
.boton { padding: 0.75rem 1.25rem; }

/* Por id (único en la página) */
#hero { min-height: 70vh; }

/* Descendiente: p dentro de .tarjeta */
.tarjeta p { color: #475569; }

/* Hijo directo */
nav > a { text-decoration: none; }

/* Varios a la vez */
h1, h2, h3 { font-weight: 700; }

/* Pseudo-clases */
a:hover { color: #db2777; }
input:focus { outline: 2px solid #db2777; }
SelectorEjemplo HTMLCuándo
.clase<button class="boton">Estilos reutilizables (lo más habitual).
#id<section id="hero">Un solo elemento especial (anclas, JS).
etiqueta<p>Base tipográfica o resets suaves.

Clase vs id en HTML

<button class="boton boton--primario">Comprar</button>
<section id="precios" class="seccion">...</section>
Especificidad (quién gana)

Si dos reglas chocan, gana la más específica: id > clase > etiqueta. Evita pelear con !important; mejor organiza clases claras. Un id muy específico dificulta reutilizar estilos.

Comentarios y cascada

Si dos reglas tienen la misma especificidad, gana la que aparece después en el CSS. Por eso el orden del archivo importa.

.boton { background: #334155; } /* primero */
.boton { background: #db2777; } /* esta gana */

Modelo de caja y espaciado

Cada elemento es una caja con contenido, padding (relleno interno), border (borde) y margin (espacio exterior).

  ┌──────── margin ────────┐
  │  ┌──── border ────┐    │
  │  │  ┌─ padding ─┐ │    │
  │  │  │ contenido │ │    │
  │  │  └───────────┘ │    │
  │  └────────────────┘    │
  └────────────────────────┘

margin, padding y border

.tarjeta {
  /* Arriba | Derecha | Abajo | Izquierda */
  margin: 1rem 1.5rem 2rem 1.5rem;
  padding: 1.25rem;          /* los cuatro lados iguales */
  border: 1px solid #e2e8f0;
  border-radius: 12px;
  background: #fff;
}

/* Atajos útiles */
.bloque {
  margin-block: 2rem;   /* arriba y abajo */
  margin-inline: auto;  /* izquierda y derecha (centrar bloques) */
  padding-inline: 1rem; /* izquierda y derecha */
}
PropiedadEfecto
marginEmpuja a otros elementos (fuera de la caja).
paddingAire entre el borde y el contenido (dentro).
borderLínea alrededor; suma al tamaño si no usas border-box.
width / heightTamaño del contenido (o de toda la caja, según box-sizing).

box-sizing: border-box (casi obligatorio)

Por defecto, width: 300px es solo el contenido: padding y border lo hacen más ancho. Con border-box, el width incluye padding y border. Así los layouts dejan de “romperse”.

*,
*::before,
*::after {
  box-sizing: border-box;
}

.caja {
  width: 300px;
  padding: 20px;
  border: 2px solid #334155;
  /* Con border-box, el total sigue siendo 300px */
}
Ponlo al inicio de tu CSS

El reset de box-sizing: border-box en todos los elementos es una de las primeras líneas de casi cualquier proyecto moderno.

display: block, inline y inline-block

  • block (div, p, section): ocupa todo el ancho disponible, salta de línea.
  • inline (span, a, strong): fluye con el texto; width/height no aplican como esperas.
  • inline-block: fluye como texto pero acepta width, height y padding vertical.
margin vertical se colapsa

Entre dos bloques seguidos, los márgenes verticales no se suman: gana el mayor. Si quieres espacio fijo, usa padding en el contenedor o gap en flex/grid.

Colores y tipografía profesionales

El “estilo pro” no es magia: es pocos colores bien elegidos, tipografía legible y contraste suficiente.

Variables CSS (custom properties)

Define la paleta una vez y reutilízala. Si cambias el acento, cambia en toda la web.

:root {
  --fondo: #0b1220;
  --superficie: #121a2b;
  --texto: #e8eefc;
  --texto-suave: #94a3b8;
  --acento: #f472b6;
  --acento-hover: #fb7185;
  --borde: rgba(148, 163, 184, 0.25);
  --radio: 12px;
  --fuente: "Segoe UI", system-ui, sans-serif;
  --fuente-display: "Georgia", "Times New Roman", serif;
}

body {
  font-family: var(--fuente);
  color: var(--texto);
  background: var(--fondo);
}

.boton-primario {
  background: var(--acento);
  color: #0b1220;
  border-radius: var(--radio);
}

.boton-primario:hover {
  background: var(--acento-hover);
}

Cómo armar una paleta sencilla

  1. Fondo y superficie (tarjetas un poco distintas del fondo).
  2. Texto principal y un tono más suave para secundarios.
  3. Un acento (botones, links activos). Opcional: un segundo acento para avisos.
  4. Borde sutil para separar sin ruido.
Herramientas útiles

Prueba paletas en coolors.co o realtimecolors.com. Revisa el contraste en WebAIM Contrast Checker (objetivo AA: ≥ 4.5:1 en texto normal).

Tipografía legible

body {
  font-size: 1rem;       /* ~16px: base cómoda */
  line-height: 1.6;      /* aire entre líneas */
  letter-spacing: 0.01em;
}

h1, h2, h3 {
  font-family: var(--fuente-display);
  line-height: 1.2;
  letter-spacing: -0.02em;
  text-wrap: balance; /* títulos más equilibrados (navegadores modernos) */
}

.lead {
  font-size: 1.125rem;
  color: var(--texto-suave);
  max-width: 40rem; /* ~65 caracteres: lectura cómoda */
}

Pocas familias1 para cuerpo + 1 para títulos suele bastar.
EscalaUsa rem: 1rem, 1.25rem, 1.5rem, 2rem…
Peso400 cuerpo, 600/700 títulos; no abuses de bold.
ContrasteTexto gris claro sobre fondo claro es ilegible.

Siempre pon un fallback

Si la fuente web no carga, el navegador usa la siguiente de la lista (system-ui, sans-serif). Sin fallback, el texto puede “saltar” o verse mal.

Flexbox

Flexbox alinea elementos en una fila o una columna: barras de navegación, centrar un bloque, repartir espacio entre ítems.

Contenedor flex

<header class="barra">
  <a class="logo" href="/">Marca</a>
  <nav class="menu">
    <a href="#a">Inicio</a>
    <a href="#b">Proyectos</a>
    <a href="#c">Contacto</a>
  </nav>
</header>
.barra {
  display: flex;
  align-items: center;      /* eje cruzado: vertical si es fila */
  justify-content: space-between; /* eje principal: horizontal */
  gap: 1rem;
  padding: 1rem 1.5rem;
}

.menu {
  display: flex;
  gap: 1rem;
  align-items: center;
}

justify-content y align-items

PropiedadValores útiles
flex-directionrow (default), column, *-reverse
justify-contentflex-start, center, flex-end, space-between, space-around
align-itemsstretch, flex-start, center, flex-end
gapEspacio entre ítems (mejor que margin entre hermanos).
flex-wrapwrap para que bajen de línea en pantallas chicas.

Centrar en la pantalla

.pantalla-centrada {
  min-height: 100vh;
  display: flex;
  justify-content: center;
  align-items: center;
  padding: 1rem;
}

flex en los hijos

.fila {
  display: flex;
  gap: 1rem;
}

.fila .crece {
  flex: 1; /* ocupa el espacio libre */
}

.fila .fijo {
  flex: 0 0 200px; /* no crece, no encoge, base 200px */
}
Regla práctica

Flexbox = una dimensión (fila o columna). Si necesitas filas y columnas a la vez (galería, dashboard), usa Grid.

CSS Grid

Grid crea layouts en dos dimensiones: filas y columnas. Ideal para galerías, páginas con sidebar y tableros.

Galería sencilla

<div class="galeria">
  <figure>1</figure>
  <figure>2</figure>
  <figure>3</figure>
  <figure>4</figure>
</div>
.galeria {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* 3 columnas iguales */
  gap: 1rem;
}

.galeria figure {
  margin: 0;
  aspect-ratio: 4 / 3;
  background: #1e293b;
  border-radius: 12px;
}

Layout con sidebar

.layout {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "cabecera cabecera"
    "lateral  contenido"
    "pie      pie";
  min-height: 100vh;
  gap: 1rem;
}

.layout__cabecera { grid-area: cabecera; }
.layout__lateral  { grid-area: lateral; }
.layout__contenido { grid-area: contenido; }
.layout__pie      { grid-area: pie; }

Columnas que se adaptan solas

.tarjetas {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 1.25rem;
}

Cada tarjeta mide al menos 240px; si cabe otra, Grid añade una columna. Sin media queries para el caso básico.

span: un ítem ocupa varias celdas

.destacada {
  grid-column: span 2; /* ocupa 2 columnas */
  grid-row: span 2;    /* ocupa 2 filas */
}
fr = fracción

1fr 2fr reparte el espacio libre: la segunda columna tiene el doble de ancho que la primera. Combínalo con px o minmax() para límites.

Diseño responsive

Responsive = la página se ve bien en móvil, tablet y escritorio. Empieza por el viewport y diseña primero para pantallas chicas (mobile-first).

Viewport (obligatorio)

<meta name="viewport" content="width=device-width, initial-scale=1">

Mobile-first con media queries

/* Estilos base = móvil */
.nav {
  display: flex;
  flex-direction: column;
  gap: 0.5rem;
}

.galeria {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

/* Tablet y más */
@media (min-width: 640px) {
  .galeria {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* Escritorio */
@media (min-width: 960px) {
  .nav {
    flex-direction: row;
    align-items: center;
    justify-content: space-between;
  }

  .galeria {
    grid-template-columns: repeat(3, 1fr);
  }

  .contenedor {
    max-width: 1100px;
    margin-inline: auto;
    padding-inline: 1.5rem;
  }
}

Unidades fluidas

UnidadUso
% / frAnchos relativos al contenedor o al grid.
remTipografía y espaciado (respecto a la raíz).
vw / vh% del viewport (con cuidado: 100vh en móvil es tramposo).
clamp()Tamaño fluido con mínimo y máximo.
 
h1 {
  /* mínimo 1.75rem, preferido 5vw, máximo 3rem */
  font-size: clamp(1.75rem, 4vw + 1rem, 3rem);
}

img {
  max-width: 100%;
  height: auto;
  display: block;
}
Prueba de verdad

En Chrome/Edge: F12 → icono de dispositivo (o Ctrl+Shift+M). Revisa 360px, 768px y 1280px. También prueba en tu celular real.

No bloquees el zoom

Evita user-scalable=no o maximum-scale=1 en el viewport: perjudica la accesibilidad de quien necesita ampliar.

Sombras, degradados y efectos

Estos detalles dan profundidad y acabado. Úsalos con moderación: demasiada sombra o blur cansa la vista.

box-shadow

.tarjeta {
  background: #fff;
  border-radius: 16px;
  box-shadow:
    0 1px 2px rgba(15, 23, 42, 0.06),
    0 8px 24px rgba(15, 23, 42, 0.08);
}

.tarjeta:hover {
  box-shadow:
    0 2px 4px rgba(15, 23, 42, 0.08),
    0 16px 40px rgba(15, 23, 42, 0.12);
}

Orden: offset-x, offset-y, blur, spread, color. Sombras suaves y multicapa se ven más naturales que un solo bloque negro.

Transiciones y efectos hover

Una transición hace que el cambio de estilo sea suave en lugar de un salto brusco. El hover es el caso más común.

transition básica

.boton {
  display: inline-flex;
  align-items: center;
  gap: 0.5rem;
  padding: 0.75rem 1.25rem;
  border: none;
  border-radius: 999px;
  background: #f472b6;
  color: #0b1220;
  font-weight: 600;
  cursor: pointer;
  transition:
    background 0.2s ease,
    transform 0.2s ease,
    box-shadow 0.2s ease;
}

.boton:hover {
  background: #fb7185;
  transform: translateY(-2px);
  box-shadow: 0 8px 20px rgba(244, 114, 182, 0.35);
}

.boton:active {
  transform: translateY(0);
}

Tarjeta con hover

.card {
  transition: transform 0.25s ease, box-shadow 0.25s ease;
}

.card:hover {
  transform: translateY(-4px);
  box-shadow: 0 16px 40px rgba(15, 23, 42, 0.15);
}

.card img {
  transition: transform 0.4s ease;
}

.card:hover img {
  transform: scale(1.04);
}

Enlaces y subrayado animado

.link-fino {
  color: inherit;
  text-decoration: none;
  background-image: linear-gradient(currentColor, currentColor);
  background-position: 0 100%;
  background-repeat: no-repeat;
  background-size: 0% 2px;
  transition: background-size 0.25s ease;
}

.link-fino:hover {
  background-size: 100% 2px;
}
Qué animar (y qué no)

Anima transform y opacity: el navegador las acelera bien. Evita animar width, height, top o left en bucles: provocan reflow y se sienten pesadas.

No olvides :focus-visible

Quien navega con teclado necesita ver el foco. Añade un outline claro en :focus-visible, no solo estilos en :hover.

.boton:focus-visible {
  outline: 2px solid #f472b6;
  outline-offset: 3px;
}

Animaciones con @keyframes

Las transiciones van de A → B al cambiar un estado. Las animaciones definen una secuencia completa con @keyframes y pueden repetirse solas.

Anatomía

@keyframes flotar {
  0%   { transform: translateY(0); }
  50%  { transform: translateY(-10px); }
  100% { transform: translateY(0); }
}

.icono-flotante {
  animation: flotar 3s ease-in-out infinite;
}
PropiedadSignificado
animation-nameNombre del @keyframes.
animation-durationCuánto dura un ciclo (1s, 800ms).
animation-timing-functionease, linear, ease-in-out, cubic-bezier(...).
animation-delayEspera antes de empezar.
animation-iteration-count1, 3, infinite.
animation-directionnormal, alternate, reverse.
animation-fill-modeforwards deja el estado final; both también aplica el inicial en el delay.

Entrada fade + subida

@keyframes entrar {
  from {
    opacity: 0;
    transform: translateY(16px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

.entrar {
  animation: entrar 0.6s ease-out both;
}

/* Retrasos escalonados */

Accesibilidad

Animaciones infinitas fuertes (parpadeo, sacudidas) pueden marear. Ofrece alternativas estáticas y respeta prefers-reduced-motion.

Animaciones de texto

El texto animado bien hecho da personalidad a un hero o a un titular. Aquí tienes los efectos más usados, listos para copiar. Combínalos con moderación: un solo efecto protagonista por pantalla.

1. Degradado animado en el texto

Límite del CSS puro

Si el texto cambia de longitud o quieres varias líneas, usa JavaScript (siguiente ejemplo). En responsive, ch + nowrap puede desbordar: prueba en móvil.

3. Typewriter con JavaScript (flexible)

<h1>
  <span id="maquina" aria-live="polite"></span><span class="cursor" aria-hidden="true">|</span>
</h1>
<script src="typewriter.js"></script>
const frases = [
  "HTML semántico",
  "CSS con intención",
  "Animaciones con criterio",
];

const el = document.querySelector("#maquina");
let frase = 0;
let i = 0;
let borrando = false;

function tick() {
  const actual = frases[frase];
  el.textContent = actual.slice(0, i);

  if (!borrando && i < actual.length) {
    i++;
    setTimeout(tick, 70);
  } else if (!borrando && i === actual.length) {
    borrando = true;
    setTimeout(tick, 1400); // pausa al terminar
  } else if (borrando && i > 0) {
    i--;
    setTimeout(tick, 35);
  } else {
    borrando = false;
    frase = (frase + 1) % frases.length;
    setTimeout(tick, 300);
  }
}

tick();
.cursor {
  display: inline-block;
  margin-left: 2px;
  animation: parpadear 0.9s step-end infinite;
  color: #f472b6;
}

@keyframes parpadear {
  50% { opacity: 0; }
}

@media (prefers-reduced-motion: reduce) {
  .cursor { animation: none; }
}

4. Letra por letra (stagger)

Envuelves cada carácter en un span y retrasas la animación con --i.

<h1 class="letras" aria-label="Impacto">
  <span style="--i:0">I</span><span style="--i:1">m</span><span style="--i:2">p</span><span style="--i:3">a</span><span style="--i:4">c</span><span style="--i:5">t</span><span style="--i:6">o</span>
</h1>
.letras span {
  display: inline-block;
  opacity: 0;
  transform: translateY(0.6em);
  animation: letra-entra 0.5s ease forwards;
  animation-delay: calc(var(--i) * 0.05s);
}

@keyframes letra-entra {
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

Para no escribir a mano cada letra, genera los spans con JS:

function envolverLetras(selector) {
  const nodo = document.querySelector(selector);
  const texto = nodo.textContent;
  nodo.setAttribute("aria-label", texto.trim());
  nodo.innerHTML = "";
  [...texto].forEach((caracter, i) => {
    const span = document.createElement("span");
    span.textContent = caracter === " " ? "\u00A0" : caracter;
    span.style.setProperty("--i", i);
    span.setAttribute("aria-hidden", "true");
    nodo.appendChild(span);
  });
}

envolverLetras(".letras");

Checklist rápido de texto animado

  • Un efecto principal por hero; el resto, estático o muy sutil.
  • Mantén el contraste: el degradado no debe bajar de ~4.5:1 sobre el fondo.
  • Usa aria-label / aria-live cuando el texto se construye por JS.
  • Respeta prefers-reduced-motion: muestra el texto final sin animar.
Combinación ganadora

Degradado estático o muy lento en el h1 + fade corto en el párrafo + CTA con hover. Se siente premium sin marear.

Animaciones al hacer scroll

En lugar de animar todo al cargar, puedes hacer que los bloques aparezcan cuando entran en pantalla. La API moderna es IntersectionObserver: eficiente y sin librerías.

HTML + clase inicial

<section class="reveal">
  <h2>Proyecto uno</h2>
  <p>Descripción breve.</p>
</section>

<section class="reveal">
  <h2>Proyecto dos</h2>
  <p>Otra descripción.</p>
</section>

<script src="reveal.js"></script>
.reveal {
  opacity: 0;
  transform: translateY(24px);
  transition: opacity 0.7s ease, transform 0.7s ease;
}

.reveal.es-visible {
  opacity: 1;
  transform: translateY(0);
}

@media (prefers-reduced-motion: reduce) {
  .reveal {
    opacity: 1;
    transform: none;
    transition: none;
  }
}
const reduce = window.matchMedia("(prefers-reduced-motion: reduce)").matches;

if (reduce) {
  document.querySelectorAll(".reveal").forEach((el) => {
    el.classList.add("es-visible");
  });
} else {
  const io = new IntersectionObserver(
    (entradas) => {
      entradas.forEach((entrada) => {
        if (entrada.isIntersecting) {
          entrada.target.classList.add("es-visible");
          io.unobserve(entrada.target); // solo una vez
        }
      });
    },
    { threshold: 0.15, rootMargin: "0px 0px -8% 0px" }
  );

  document.querySelectorAll(".reveal").forEach((el) => io.observe(el));
}

Retrasos escalonados en una fila

.reveal-grupo .reveal:nth-child(1) { transition-delay: 0s; }
.reveal-grupo .reveal:nth-child(2) { transition-delay: 0.1s; }
.reveal-grupo .reveal:nth-child(3) { transition-delay: 0.2s; }
threshold y rootMargin

threshold: 0.15 exige que se vea un 15 % del elemento. rootMargin negativo abajo hace que la animación arranque un poco antes de llegar al borde inferior.

Contenido oculto y SEO/a11y

No dejes texto crítico solo con opacity: 0 sin plan B: si JS falla, el usuario no ve nada. El bloque de prefers-reduced-motion (o mostrar visible por defecto y ocultar solo si hay JS) evita ese agujero.

Modo oscuro y claro

Lo profesional es ofrecer ambos modos con variables CSS, respetar la preferencia del sistema y recordar la elección en localStorage.

Paleta con variables

  --superficie: #ffffff;
  --texto: #0f172a;
  --texto-suave: #475569;
  --acento: #db2777;
  --borde: #e2e8f0;

  --fondo: #0b1220;
  --superficie: #121a2b;
  --texto: #e8eefc;
  --texto-suave: #94a3b8;

Evitar el parpadeo al cargar

Pon este script en el <head>, antes del CSS visible, para aplicar el modo antes del primer pintado:

<script>
(function () {
  var modo = "oscuro";
  try {
    modo = localStorage.getItem("tema") ||
      (window.matchMedia("(prefers-color-scheme: light)").matches
        ? "claro"
        : "oscuro");
  } catch (e) {}
  document.documentElement.setAttribute("data-modo", modo);
})();
</script>

Botón para alternar

<button type="button" id="cambiar-modo" aria-label="Cambiar modo claro u oscuro">
  Cambiar tema
</button>
<script src="tema.js"></script>
const boton = document.querySelector("#cambiar-modo");

function aplicar(modo) {
  document.documentElement.setAttribute("data-modo", modo);
  try {
    localStorage.setItem("tema", modo);
  } catch (e) {}
}

boton.addEventListener("click", () => {
  const actual = document.documentElement.getAttribute("data-modo");
  aplicar(actual === "oscuro" ? "claro" : "oscuro");
});

Imágenes y fondos

En modo oscuro, baja un poco el brillo de fotos grandes (filter: brightness(0.9)) o usa assets distintos. Los logos con fondo blanco suelen necesitar una versión clara.

Checklist para un estilo profesional

Estas son las diferencias habituales entre una página “hecha a mano alzada” y una que se siente diseñada.

Consistencia

  • Misma paleta (variables) en toda la web; no inventes un rosa distinto en cada sección.
  • Misma familia tipográfica y escala de tamaños.
  • Mismos radios de borde y mismos espaciados (8 / 12 / 16 / 24 / 32 px o rem equivalentes).
  • Misma altura y estilo de botones primarios / secundarios.

Espaciado y ritmo

  • Más aire entre secciones que entre párrafos de una misma sección.
  • max-width en el texto corrido (~60–70 caracteres) para no leer de lado a lado en monitores anchos.
  • Alinea a una rejilla mental: márgenes laterales iguales, columnas con el mismo gap.

Contraste y jerarquía

  • Un h1 claro; el resto baja de tamaño e importancia.
  • Texto sobre fondo con contraste AA (≥ 4.5:1).
  • El CTA principal destaca por color y posición; no compitas con cinco botones iguales.

Antes de publicar, revisa en 2 minutos

Abre en móvil, tabula con el teclado, apaga las animaciones del sistema y mira si todo sigue usable. Si pasa esa prueba, ya estás por encima de la media.

Publicar tu página gratis

GitHub Pages sirve sitios estáticos (HTML, CSS, JS) desde un repositorio. Ideal para portafolios y guías.

1. Sube el proyecto a GitHub

Si aún no tienes repo, en la carpeta del sitio:

git init
git add .
git commit -m "Primera versión del sitio"
git branch -M main
git remote add origin https://github.com/TU-USUARIO/TU-REPO.git
git push -u origin main
Estructura típica

Para Pages en la rama main, el index.html suele estar en la raíz del repo o en la carpeta /docs. Si usas otra carpeta, configúrala en los ajustes de Pages.

2. Activa GitHub Pages

  1. En GitHub: tu repositorio → Settings → Pages.
  2. En Build and deployment → Source: elige Deploy from a branch.
  3. Branch: main, carpeta / (root) o /docs → Save.
  4. En uno o dos minutos verás la URL: https://TU-USUARIO.github.io/TU-REPO/.

3. Rutas relativas

Si el sitio no está en el dominio raíz, los enlaces absolutos a /estilos.css pueden fallar. Prefiere rutas relativas:

<link rel="stylesheet" href="estilos.css">
<img src="img/foto.jpg" alt="...">
<a href="proyectos.html">Proyectos</a>

4. Actualizar la web

git add .
git commit -m "Mejora el hero y el modo oscuro"
git push

Pages se regenera solo tras el push. Si no ves cambios, fuerza recarga con Ctrl+F5 o espera un minuto.

5. Dominio propio (opcional)

En Pages puedes indicar un dominio personalizado y crear en tu DNS un registro CNAME hacia TU-USUARIO.github.io. GitHub muestra las instrucciones exactas.

Más allá de Pages

Netlify, Cloudflare Pages y Vercel también publican sitios estáticos con HTTPS gratis y suelen conectar el repo en unos clics. El flujo es el mismo: push → deploy automático.

No subas secretos

Nunca subas claves API, contraseñas o archivos .env al repositorio público. Lo que está en GitHub Pages es visible para todo el mundo.
